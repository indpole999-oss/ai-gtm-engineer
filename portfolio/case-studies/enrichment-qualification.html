02 / DATA OPERATIONS

Enrichment without pretending missing data exists.

An honest, test-only enrichment waterfall and qualification flow: record what was attempted, preserve nulls, and make the fit decision explainable.

AUTHOR / ANIL JANGAENVIRONMENT / FICTIONAL OFFLINE DEMOOUTCOME / TECHNICAL EXAMPLE, NOT CLIENT ROI

EVIDENCE STATUS

Offline / Reproducible

Python source, deterministic fixture data and unit tests.

Reproduce the code ↗

ETHICAL BOUNDARY

No real contacts, client data, paid providers or external actions.

The business problem

A sales contact database is only as useful as its coverage, provenance and freshness. A single provider may return no data, which can break downstream qualification—or tempt a workflow to silently manufacture an answer.

The reference architecture

Source-tagged accountFictional fixtures only
↓
Mock primary providerNo HTTP request or enrichment charge
↓
Mock fallback when contact missingAttempts recorded; missing remains null
↓
ICP qualification rubricExplain industry, size, signal, coverage
↓
Output + evidence labelsReal-world verification explicitly false

What the code really does

The enrich_mock function uses fictional input records. If a fixture includes a sample contact, it records one mock-provider attempt; otherwise it records two mock-provider attempts. It never queries Apollo, Clay or any external API. All example contact addresses use the reserved .example domain.

Why this is safer than a fake “live” demo

The sample exposes the control flow without sending credentials or spending credits. Returning None when there is no contact is a useful default. The test suite confirms no external calls and no external CRM writes occur across fixture accounts.

What would make this a real integration

□ Approved sandbox and provider scopes

□ Response schema normalization and data validation

□ Explicit provider costs and retry budget

□ Duplicate reconciliation against an actual CRM sandbox

□ Consent, privacy, suppression and audit boundaries

□ Readback of inserted records and measured coverage

These are acceptance criteria, not completed deliverables.
