03 / AGENT SAFETY

Human approval is a state transition, not a green toast.

A controlled example of draft creation, explicit review and zero-side-effect approval, built so the system cannot accidentally contact prospects.

ETHICAL BOUNDARY

No real contacts, client data, paid providers or external actions.

The business problem

Many AI workflow demos blur the difference between generating a message and sending it. That distinction matters when an agent is connected to a real customer's email, CRM or calendar. A truthful platform has to distinguish intention, authorization, provider acceptance and verified outcome.

What the test actually verifies

The Python example clones the draft, requires a nonempty reviewer, and updates only the clone. The original remains pending. A separate browser example disables repeated approval after the first click and explicitly states that no external action occurred.

The workflow gallery also tests a local dictionary-based CRM upsert for idempotency and generates a UTC meeting preview; neither is a real third-party API write.

Why this is not a production approval system yet

Production would require identity-bound approval records, RBAC checks, durable storage, separate consent from send execution, provider receipts, idempotency keys, retry behavior, and structured audit logs. These are not implied by a unit test that changes an in-memory object.

The next integration milestone

With authorized sandbox access, run an approval through the actual backend, confirm the persisted state, execute one specifically approved test action, verify the provider's returned receipt and CRM readback, and check duplicate prevention. Never use a real email recipient during uncontrolled tests.
