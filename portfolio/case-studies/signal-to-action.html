01 / The actual GTM problem

When sales teams automate buying-signal outreach, the visible email is often the smallest part of the system. The expensive failures happen earlier: an account is wrongly merged with a similar business, a lead belongs to an open opportunity, a signal is stale, a contact unsubscribed, or a CRM task gets created twice.

This project models the integration boundary required to prevent those errors. It uses entirely fictional companies and sources, so the engineering decisions can be demonstrated without claiming real prospect intelligence.

03 / A data-quality decision that mattered

Exact canonical domains merge northstar.example and www.northstar.example, but they do not merge northstar-partner.example. For contacts, normalized email is the deduplication key; suppression flags and consent restrictions propagate conservatively across duplicates. A lead cannot escape an unsubscribe or DNC flag because a second record is less restricted.

06 / What failed in the negative test cases

Each of these scenarios correctly stopped or reduced actions: all contacts unsubscribed; missing signals; missing source labels; stricter ICP thresholds; lack of consent; stale signal dates; quota restrictions; orphan CRM account reference; and a DNC flag on a duplicate record. Separate tests rejected unsafe live-write mode and any nonzero external-credit allowance. Repeated runs returned identical outputs.

07 / What production would still require

The current package deliberately uses no live providers. A real account-intelligence-to-CRM journey would need authorized enrichment and CRM sandbox access, provider response/receipt validation, persistent idempotency storage, retry queues, actual approval identity, suppression readback, permission checks, rate-limit handling, and a documented rollback path. Isolated local n8n runtime execution passed in both baseline and all-DNC negative-path scenarios; the original n8n instance and its 20 workflows were unchanged. Provider integration readbacks remain unverified.

08 / Verified local n8n execution

Two executions passed in n8n 2.25.7 using a separate local test database. The baseline processed 42 graph nodes and produced 3 human-review drafts and 7 suppressed contacts. A negative-path run with all contacts marked DNC took the empty-queue branch and produced zero drafts. Both recorded zero emails, CRM writes, calendar writes, provider calls or credit usage.
